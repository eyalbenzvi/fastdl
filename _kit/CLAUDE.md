# CLAUDE.md – אב-טיפוס "רישיון עד הבית"

אתה בונה אב-טיפוס HTML לחיץ, רספונסיבי (mobile-first), בעברית RTL, לאתר השירות "רישיון עד הבית" של דפוס בארי. אזרחים נכנסים לאתר כדי לבדוק מה מצב הרישיון שלהם ולבחור משלוח או איסוף.

**העיצוב כבר סגור.** המטרה היא לממש אותו 1:1 כאתר סטטי נקי ומתוחזק, לא לעצב מחדש.

---

## 1. מקורות האמת (לפי סדר עדיפות)

1. **`mockups/`** – איך זה נראה. 67 מסכים ומצבים × דסקטופ 1280 ומובייל 390. הגלריה: `mockups/index.html`, המיפוי: `mockups/manifest.json`.
2. **`docs/05_screens.md`, `docs/06_status_states.md`, `docs/07_order_flow.md`** – מה יש בכל מסך ואיך הוא מתנהג.
3. **`reference/rendered-html/<id>.html`** – ה-markup והנוסח המדויקים של כל מסך ומצב. **העתק נוסח עברי משם מילה במילה.** אל תנסח מחדש.
4. **`reference/canvas-source/*.dc.html`** – קוד המקור של העיצוב (כולל הלוגיקה ב-`renderVals()`). שימושי להבנת לוגיקה; זה פורמט פנימי, אל תעתיק את המבנה שלו (`<x-dc>`, `{{ }}`, `<sc-if>`).
5. **`design/tokens.css` + `design/components.css`** – ה-CSS. השתמש בהם כבסיס; אל תמציא ערכי צבע, ריווח או גודל.
6. `docs/source/02_Original_Brief.md` – ה-Brief המקורי. במקרה של סתירה, סעיפים 1–5 גוברים עליו (הם מאוחרים יותר).

אם משהו לא מוגדר באף מקור – בחר את הפתרון הפשוט שתואם לרכיבים הקיימים, וכתוב את ההחלטה ב-`DECISIONS.md`. **אל תמציא מחירים, כתובות, שעות או כללים.** השתמש ב-`<span class="tbc">[לאישור]</span>`.

## 2. סטאק ומבנה (פירוט מלא: `docs/02_architecture.md`)

- **HTML5 + CSS + JavaScript וניל. בלי build, בלי framework, בלי npm dependencies באתר עצמו.**
- סקריפטים קלאסיים (`<script defer src>`), **לא** ES modules – כדי שהאתר יעבוד גם בפתיחה ישירה מ-`file://`.
- עמוד HTML לכל מסך (רשימה מלאה ב-`docs/02_architecture.md` §3). Header, Footer וסרגל ההדגמה מוזרקים מ-`js/layout.js`.
- נתוני דמה: `js/mock-data.js` (`window.FD_DATA`). בלי `fetch`.
- פונטים מקומיים מ-`fonts/` (בלי Google Fonts בזמן ריצה).
- אייקונים: SVG inline מתוך `design/icons/` (או sprite עם `<use>`). בלי ספריות אייקונים ובלי אימוג'י.
- Dev server לבדיקות: `npx --yes http-server -p 8080 -c-1 .` (או `python3 -m http.server 8080`).

```
/                     ← שורש האתר (העמודים)
css/tokens.css        ← מ-design/tokens.css
css/components.css    ← מ-design/components.css (+ הרחבות)
css/pages.css         ← סגנונות ספציפיים לעמודים
js/mock-data.js       ← מ-data/mock-data.js
js/layout.js          ← Header, Footer, תפריט, סרגל הדגמה
js/ui.js              ← אקורדיון, מגירות, מודאל, טוסט, העתקה, focus trap
js/validation.js      ← ת"ז, נייד, OTP
js/pages/*.js         ← לוגיקה לכל עמוד (status.js, order.js, login.js …)
fonts/  icons/  img/  ← מ-design/fonts, design/icons, design/brand + assets/documents
```

## 3. כללים שאסור לשבור

1. **כפתור Primary אחד לכל היותר בכל מסך** (או בכל מצב של אותו מסך). כל השאר Secondary או קישור.
2. **מסך המצב בנוי מתבנית אחת** בכל המצבים: שורת זהות ← תג + H1 ← ציר התקדמות ← "מה עכשיו?" ← פרטים ← "משהו לא ברור?".
3. **אין ספירה לאחור בלי תאריך ושעה מוחלטים לצידה.**
4. **שדה בלי ערך לא מוצג** (לא "-----", לא "לא רלוונטי").
5. **שום קישור בתוך תהליך ההזמנה לא מוציא מהעמוד.** מידע משני נפתח במגירה, והבחירות נשמרות.
6. **RTL אמיתי:** `<html lang="he" dir="rtl">`, logical properties בלבד (`margin-inline-start` וכו'), "קדימה/המשך" = חץ שמאלה, "חזרה" = חץ ימינה. מספרים (ת"ז, טלפון, תאריכים, מספרי הזמנה/מעקב) עטופים ב-`<span class="num" dir="ltr">`.
7. **נגישות AA:** ניגודיות ≥4.5:1, פוקוס גלוי (`3px #FFB020`, offset 2px), יעדי לחיצה ≥44px, `<label for>` לכל שדה, שגיאות עם `role="alert"` ו-`aria-invalid`, סטטוס לא מועבר בצבע בלבד, קישור "דלג לתוכן הראשי".
8. **`--c-brand-cyan` (#10A9E0) דקורטיבי בלבד.** לעולם לא טקסט ולא רקע של כפתור.
9. **לוגו משרד התחבורה רק כ-placeholder מקווקו** עם הטקסט "לוגו משרד התחבורה – בכפוף לאישור".
10. **כל ערך [לאישור] נשאר מודגש** עם `class="tbc"`. אל תמלא אותו בערך שהמצאת.
11. **אל תשתמש בתמונות מ-`assets/current_site_before/`** באתר. הן "לפני" בלבד. מסמכים: רק שתי התמונות המושחרות מ-`assets/documents/`.
12. **בלי placeholder במקום label.** בלי טקסט משפטי ארוך בגוף המסך (רק במגירה).
13. `localStorage`/`sessionStorage` מותרים רק לשמירת בחירות ההזמנה, ותמיד עטופים ב-`try/catch`. האתר חייב לעבוד גם בלעדיהם.

## 4. איך לעבוד

- **עבוד לפי אבני הדרך ב-`docs/11_milestones.md`, לפי הסדר.** בסוף כל אבן דרך: הרץ את הבדיקות שלה, צלם מסכים (ראה §5), השווה להדמיות, ודווח בקצרה מה נבנה, מה נבדק ומה פתוח.
- **לפני שאתה בונה מסך:** פתח את ההדמיה שלו (desktop + mobile) ואת `reference/rendered-html/<id>.html` שלו.
- **רכיב שחוזר פעמיים או יותר** נבנה פעם אחת (מחלקת CSS + פונקציית JS), לא בהעתק-הדבק.
- **שמות:** קבצים ב-kebab-case באנגלית, מחלקות CSS בסגנון BEM כמו ב-`components.css`, טקסטים בעברית.
- **לא לגעת** בתיקיות `mockups/`, `reference/`, `docs/source/` – הן רפרנס.
- כל החלטה שלא כתובה במסמכים → שורה ב-`DECISIONS.md` (תאריך, החלטה, סיבה).

## 5. בדיקה ויזואלית (חובה בסוף כל אבן דרך)

סקריפט מוכן לשימוש חוזר: `docs/09_qa_acceptance.md` §4.
